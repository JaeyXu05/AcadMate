供队内审阅。通过后按修改案批次开工，不另换赛道。代码根目录：Mentor-matching-platform-107-main/。创意叙事另见 107_完整创意总结.html；本文是可执行合同。

请审的两件事：① 规划案里的产品定义、边界、用户链是否锁定；② 修改案的批次、改哪些文件、验收标准、明确不做是否可以开工。有异议标在对应批次上，不要口头另起一条产品。

一、规划案（拟锁定）

1.1 产品定义

产品服务学生的科研成长。导师匹配是现有主入口，必须保留并加强。多智能体是比赛与系统的核心，用来完成链上各阶段工作。Harness 用来组织多个科研 Skill、共享上下文和长期成长状态。GitHub / 黑客松项目只提供可借鉴的组件、交互和工程机制，不能改变服务对象。

代码调整以增加框架和能力为主：继承 Paper Claw、导师工作流、Evidence、Review、Retry、AgentRun。不能把已有导师平台替换成通用 Agent OS、coding agent 或课程刷题产品。

入口是找导师，主干是学生科研成长，发动机是多智能体，骨架是 Harness，记忆是写回后的成长状态。

1.2 正确的扩展形态：一条用户链

建立科研画像
  → 探索方向
  → 匹配导师          （现有主入口，加强）
  → 阅读论文与项目    （接入已有 Paper Claw）
  → 形成研究任务
  → 调用多智能体完成阶段工作
  → Evidence / Review / Retry
  → 把结果写回成长状态
  → 下一次 Harness 根据新状态重新组织 Skill 和 Agent

学生不是在九个工具页之间手动切换。Harness 按当前成长状态决定下一截用哪个 Skill、拉起哪些 Agent。学生可以前进或退回某一截加强，但始终是同一个人、同一份状态。

「学习」在本规划中只指：沿着科研链补方向、论文、方法、项目里缺的那一块。不做独立的课程出题 / 掌握度 Tutor。

1.3 各层职责

层职责不做什么
导师平台前端学生进门：搜索、详情、对比、星图、邮件、PDF、推荐。全部逐步挂到同一次学生状态 / AgentRun不新开第二套网站；不删现有页面
导师工作流匹配导师及后续阶段的多智能体引擎（Intake→Plan→Domain→Research→Matching→Review→Retry→Composer）不推倒重写成 LangGraph 主链
Paper Claw阅读论文与项目的多智能体 Skill，接到同一 Harness不继续作为互不相干的第二前端
Evidence / Review / Retry / AgentRun整条链的可信层与一次运行对象，不限于找导师不被 Harness 替代
HarnessSkill 注册与切换、共享上下文、长期状态、按新状态组织下一轮 Agent自己不调 LLM、不规划、不做检索
检索层导师 / 论文 / 项目 / 用户经历分库检索，供 Skill 使用不做成一个万能向量桶；画像本身不整包 embedding

1.4 检索原则（规划层，必须先于加 Skill）

  • 导师库：结构化教师卡 + 证据。稀疏检索可保留，但必须有 top-k 和命中门槛；噪声命中不得让系统跳过官网 / 论文补全。
  • 论文库：复用已有 chunk / embedding（RetrievalService），供阅读 Skill 引用。
  • 项目库：学生作品、开源仓库、复现对象；本仓几乎还没有，后期按任务补。
  • 用户经历：画像是结构化成长状态（能力、证据、时间）。只有笔记、报告、自由文本才进经历检索。
  • 对外诚实：导师主路径现阶段是「内部语料检索」，不是生成式 RAG。论文问答才是向量 RAG。禁止用 adapter 把坏检索封进所有未来 Skill。

1.5 多智能体怎么用

阶段工作由不同目标、工具、权限的 Agent 完成：Researcher 检索，Reviewer 只读账本，Matcher 不算改证据，Composer 不编造导师。已知路径（内部语料、已固化官网）可以走确定性步骤；不确定、需要对质的阶段才上模型或多智能体并行。默认模型推理保持关闭（PAPER_CLAW_MENTOR_WORKFLOW_MODEL_REASONING_ENABLED=false），保证离线可复现；需要时作为加分开关，不是默认。

1.6 明确不做（规划边界）

  • 不把产品中心从「学生找导师并沿链成长」改成「通用 Research Mission OS」。
  • 不做课程 Review / 出题 / 掌握度教学系统。
  • 不新做 Voice Agent、Browser-use 主路径、换掉现有编排器。
  • 不为每个请求固定堆 5 个聊天人设。
  • 不把论文 embedding 硬接到导师搜索主链来冒充已经做了 RAG。
