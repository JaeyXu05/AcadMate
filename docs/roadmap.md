# 路线图

AcadMate 的目标是成为一个**自进化的科研助手**：它记录你真实做过什么，理解你目前在哪，把一个模糊的科研目标变成可执行、可验证的任务，并在任务结束后让人获得新的能力证据、让 Agent 获得新的可复用技能、让社区获得一条可继续复用的路径。

这份路线图把项目从"能运行的原型"到"开放科研成长生态"的演进分成几个阶段。它不是功能堆砌清单，而是产品重心的迁移。

## 当前阶段：可验证的科研任务底座

代码已经具备一个完整的多智能体后端和一套面向科研入门的功能。这一阶段的重心是**让后端已有的可信机制变成用户能看见、能理解的东西**。

已经具备：

- **导师检索工作流**：意图理解 → 规划 → 领域专家 → 导师调研 → 匹配 → 证据审核 → 结果撰写的九阶段状态机，每个阶段发出结构化事件并持久化。可在确定性模式下离线运行，不依赖模型 Key。
- **证据审核**：独立审核角色检查意图完整性、身份核验、证据引用闭环、论文时效、结论一致性；审核不通过按指定阶段返工，而不是放大模型输出。
- **八维匹配分**：研究方向、方法、应用场景、近期活跃度、学生背景、约束、招生意愿、证据完整度，保留评分分项与负面因素。
- **论文与 PDF**：PDF 页级语义召回、可选模型结构化重排、导师匹配与证据审核；多篇合并分析，每条结论绑定 PDF 页码证据。
- **科研伴学**：科研画像、计划拆解与提醒、日报/周报/月报、导师联系邮件、Zotero 文献同步、3D 研究星图。
- **可恢复运行时**：类型化状态、EvidenceLedger、ReviewDecision、RetryController、事件总线、`state_version` 乐观锁，支持中断后继续与查询审计轨迹。

近期方向：

- 把 Plan、Evidence、Review、Retry、Artifact、Timeline 从"藏在 Chat thinking 文本里"变成前端可见的工作台内容。
- 统一输入：PDF、URL、文字进入同一个科研任务，而不是几个互相割裂的页面。
- 任务回放（Mission Replay）：所有运行事件持久化，可按时间轴回放，用于演示、调试与评估。
- 让星图从"展示导师关系"演进为任务的空间界面：证据被打回时节点变化，新证据加入时路径与排名重新计算。

## 下一阶段：Research Genome

让系统拥有一个真正的科研能力画像。它不只是"会 Python / 对 CV 感兴趣"，而是区分：看过、理解过、实现过、复现过、调试过、做过实验、做过创新，并且每个能力都尽量绑定真实 Artifact 或 Evidence。

这样每完成一个任务，系统都能明确回答：**这次任务到底让我的科研状态发生了什么变化。**

## 再下一阶段：Counterfactual Research Navigator

有了 Research Genome 后，方向与导师推荐不再只输出一个匹配分数，而是回答：

- 为什么我现在和这个方向距离比较远？
- 如果只补一项能力，哪一项最能改变结果？
- 如果我做 A / B / C 三种不同的下一步，三个月以后我的方向匹配会分别怎样变化？

"未来自己的不同分支"会成为这个项目最具吸引力的一部分。

## 之后：Mission Forge

系统发现缺口后，不只说"建议你加强多模态"，而是直接把差距生成一个小型、真实、可验收的科研任务：指定论文、repo、实验变量、结果图、失败记录、最终报告。完成后经过证据审核，确认这次经历真的足以写回 Research Genome。

## 长期：开放科研成长生态

要成为真正的开源项目，必须让别人能贡献"能力"，而不只是帮忙改 React 页面或 FastAPI 接口。

- **Forkable Mission**：一次成功的科研任务可以像 Git 仓库一样被 Fork。别人把"某论文复现任务"复制成自己的版本，把"CV 导师调查"改成 NLP，而不需要从聊天重新开始。
- **Research Pack**：社区贡献 CV Pack、Security Pack、RecSys Pack。每个 Pack 包含数据源、领域术语、Evidence Rules、典型任务、Eval cases 和工具。
- **Skill Evolution**：Agent 第一次处理未知任务时允许探索；成功后把稳定轨迹提炼成可复用 Skill。系统使用越久，越多动作从"昂贵探索"变成"稳定能力"。
- **Negative Knowledge**：失败也留下价值——哪个网页长期失效、哪个 repo 无法复现、哪个指标不能支持某个结论、哪条路线已被验证无效。后来的用户和 Agent 不必重复踩坑。

最终形成的开源循环是：

> 一个人完成任务 → 人的 Genome 变化 → Agent 得到新 Skill → 社区多一个可 Fork 的任务 / Research Pack / 失败经验。

## 不做的事

明确边界，避免变成"万能 Agent OS"：

- 不为了堆功能而堆功能。语音、Browser、Memory、MCP 等能力单独拿出来已不稀缺，只有在它们服务于"理解科研状态、计算差距、生成可验证任务"这个母题时才引入。
- 不放弃证据边界。模型负责理解与表达，确定性代码和审核器负责事实边界；没有证据就不能推荐，审核不通过就返工。
- 不内置任何特定高校的导师数据。导师数据由社区或用户按数据流水线接入目标机构（见 [`paper-claw-master/data_scripts/README.md`](../paper-claw-master/data_scripts/README.md)）。

## 版本边界一览

| 阶段 | 核心目标 | 必须有 | 暂不追求 |
|---|---|---|---|
| 当前 | 可验证的科研任务底座 | 多智能体工作流、证据审核、任务工作台、统一输入、任务回放 | 完整长期 Memory、开放社区 |
| 下一 | Research Genome | 科研能力画像、能力绑定 Artifact/Evidence | 跨用户可复用 |
| 再下一 | Counterfactual Navigator | 差距建模、反事实推荐 | 覆盖全部学科 |
| 之后 | Mission Forge | 差距生成可验收任务 | 无边界任务生成 |
| 长期 | 开放科研成长生态 | Forkable Mission、Skill/Tool/Research Pack 注册表、Eval、Negative Knowledge | 跨用户 Research Commons（核心闭环跑通后再扩） |

本路线图源于项目早期的产品研究与演进设想（完整研究记录见 `docs/future/`），并随代码实现持续校准。它不是接口或排期承诺；判断当前行为请直接查看代码、配置和测试。
