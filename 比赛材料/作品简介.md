# 作品简介

## 作品名称

科研导师推荐与科研伴学平台

## 一、作品背景与解决的问题

对本科生而言，科研入门的第一步往往不是“读论文”，而是“我该找谁、从哪开始”。但校园中的导师信息分布在官网、学术平台、论文数据库和口口相传中，学生很难判断：这位导师是否还在做相关方向？方向是否真的匹配我？我该读什么论文来验证？

现有检索工具大多只是“关键词 + 列表”，无法理解“我对多模态大模型和智能体感兴趣，希望有本科生科研指导”这类真实需求，也无法解释“为什么推荐这位导师”。同时，通用大模型直接回答容易编造导师身份、研究方向和论文。

本作品用“多智能体工作流 + 可审核科研知识库”解决上述问题：让多个智能体分工完成意图理解、领域研究、导师调研、证据审核与结果表达，保证推荐有证据、可解释、可复盘。

## 二、核心功能

1. 自然语言导师检索
学生用一句话描述研究兴趣，系统通过多智能体工作流返回匹配导师，展示匹配分、依据和证据来源。

2. 可信导师知识库
系统收录 972 位已核验导师和 1969 条证据，覆盖身份信息、官方研究方向、方法和论文记录。导师详情、推荐和邮件内容均使用真实数据。

3. 导师详情、收藏、对比与 3D 科研星图
帮助学生浏览导师主页式信息，收藏备选导师，并直观观察研究方向之间的分布关系。

4. 科研画像
根据学生专业、兴趣与成长记录生成能力画像，指出方向、技能缺口和下一步行动，只引用用户填写或平台审核的内容。

5. 论文阅读与 PDF 合并分析
上传论文 PDF 后抽取页级文本，进行本地多语种语义检索与导师匹配；支持多篇论文合并分析，每条匹配结论绑定 PDF 页码证据。

6. 科研计划与进展报告
把研究计划拆成可执行任务，自动生成日报、周报、月报，并可将报告发送到注册邮箱。

7. 导师联系邮件与文献同步
根据已读论文和导师研究方向生成联系邮件草稿；支持 SMTP/IMAP 收发邮件队列，并可连接 Zotero 增量同步文献。

## 三、使用的模型与 API 调用方式

### 对话模型

- 当前默认使用 DeepSeek 模型（`deepseek-v4-flash`，可选 `deepseek-v4-pro`），通过 OpenAI 兼容接口调用：

```text
Base URL: https://api.deepseek.com
Model:    deepseek-v4-flash / deepseek-v4-pro
API:      POST /chat/completions
```

- 调用方式：使用 `openai` SDK 的 `chat.completions.create`，传入系统提示、用户任务和结构化输出要求；需要固定 JSON 的模块使用 `response_format: {"type":"json_object"}`，并关闭隐藏思考以避免思考内容抢占输出额度。
- 同一套接口抽象兼容其他 OpenAI 兼容服务，可配置 Base URL、Model 与 API Key。
- 用户可以在账号菜单中保存自己的模型 API；科研对话、科研画像、PDF 合并分析、科研计划、进展报告和论文阅读等模型功能优先使用该账号配置。

### 向量模型

- 本地多语种向量模型：`BAAI/bge-small-zh-v1.5`，使用 FastEmbed 加载，用于导师知识库和论文正文的语义检索；
- 向量索引在安装阶段自动预热，避免首次使用超时。

## 四、Agent 工作流如何保证结果可靠

作品不是把用户问题一次性丢给模型，而是按职责拆成多个智能体角色：

```text
意图理解 -> 任务规划 -> 领域专家 -> 导师调研
-> 匹配评分 -> 证据审核 -> 结果撰写 -> 完成
```

系统内部增加了独立的“证据审核”环节，按以下规则把关：

- 导师身份只能由官方教师目录/主页证据确认；
- 论文只能补充研究方向，不能反向证明导师身份；
- 论文证据超过 5 年时效会被降权或丢弃；
- 每条推荐都要绑定证据引用，审核不通过时按指定阶段返工；
- 最终导师分数综合研究方向、方法、应用场景、活跃度、学生背景、约束、招生意愿与证据完整度八项。

该设计让“Agent 能力”与“事实可靠性”分离：大模型负责复杂理解与表达，确定性代码和审核器负责事实边界，避免检索型 Agent 编造导师。

## 五、创新点

1. 校园科研场景切入
把“找导师”从一次搜索升级为从找导师、读论文、定方向到复盘的完整科研入门服务，解决本科生难以判断导师真实匹配度的痛点。

2. 多智能体协作式工作流
将导师检索拆分为意图理解、领域专家、导师调研、证据审核、结果撰写等智能体角色，由编排器管理阶段、重试与审核，而不是把复杂任务塞进一次模型调用。

3. 证据审核机制
系统坚持“没有证据就不能推荐”，通过身份核验、证据引用闭环、论文时效与作者归属校验，显著降低大模型幻觉风险。

4. 可观测、可解释的交互
前端实时展示 Agent 阶段、证据就绪事件、评分分项与不确定性，用户能理解推荐依据，并可通过详情页核对来源。

5. 本地优先的部署与隐私设计
API Key 按账号加密保存、接口不回传明文；导师知识库支持无模型 Key 的确定性离线运行；一键启动自动完成环境准备与冒烟测试。
